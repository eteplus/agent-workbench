# 异常恢复

在超时、无进展、未知结果或部分执行时加载。目标是从已有证据续接，只重做缺失的部分。

- **无进展**：连续两个预算检查点没有可验证进展时暂停，分析阻塞，考虑缩小范围、补充信息、调整工具或升级模型。
- **硬超时**：Provider、Herdr、Pi、MCP、Shell 的硬超时由对应环境控制；把已知限制写入 Contract。
- **长时间运行的命令**：构建、测试、安装、服务启动和浏览器等待优先使用可轮询的进程/Session。工具等待超时后先检查原进程状态和输出，再决定继续等待或重试。
- **部分执行**：检查工作区、Diff、进程/Session、产物和工具结果，列明已执行、未执行和未验证事项，从现有状态恢复。
- **工具错误**：最多重试一次，重试前确认操作是否已执行；长任务仍在运行时继续观察原 Session。
- **投递结果未知**：Agent Prompt 的 timeout / stalled 只表示等待或观测失败。先读结构化状态和约定产物，再核对本轮委派输入、产物更新和执行证据；同一 Task / Subtask ID 的旧 DONE 报告不能证明本轮完成。仍无法判断时标为 `NOT VERIFIED` 并暂停重发。
- **模型错误**：检查 Provider、Model 和参数映射，使用已配置的 Fallback 并记录。Provider 错误或 429 之后的 idle 表示中断，保留已完成证据，从缺失的交付处恢复；必要报告缺失时不能通过 Gate。
- **外部写入**：按 `core/permissions.md` §3 处理；非幂等操作超时后先查询当前状态。
- **Session 清理**：任务完成或明确暂停后，只关闭本任务创建且不再需要的 Session / Pane；保留仍需继续的 Session、本地证据，以及用户或其他任务的 Session。
