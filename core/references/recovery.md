# 异常恢复

在超时、停滞、投递状态未知或异常中断时加载，目标是从已有工作区和产物续接，只补做缺失部分。

- **分段等待与停滞处理**：使用 `scripts/wait-agent.sh` 并设置合理的 `max-cycles`（如单次约 5 分钟返回 `still_working` 退出码 `1`），避免触发宿主 Bash 硬超时。收到停滞退出码 `3` 时，先检查子 Agent 状态与已有改动，发送检查点提示要求其汇报阻塞或先交付阶段成果；连续两次停滞无进展时暂停并考虑缩小范围或升级模型。
- **投递结果未知**：`agent prompt` 后用 `agent get` 核实运行状态，不加 1 秒级 `--wait`。超时后先检查原 Agent 是否仍在工作及产物是否已更新，仍在运行则继续观察，不盲目重发同一任务。
- **部分执行与模型错误**：Provider 429 或中断后，核对当前 `git diff`、检查日志与已写报告，复用有效进展，只从中断点恢复；首选模型不可用时按 `core/model-routing.md` §3–4 切换 Fallback 并记录。
- **外部操作**：非幂等外部写入超时或报错时，先回读外部当前状态，确认未生效后再重试（`core/permissions.md` §3）。
- **Session 清理**：任务完成或明确终止时，使用 `scripts/cleanup-agents.sh` 关闭本任务创建的子 Agent 与 Pane（不会误关 Main 自身 Pane），保留本地产物与 Session 记录供后续追溯。
