# 项目记忆

本文件是项目记忆的唯一策略来源：跨任务保留的有限当前知识。任务过程与审计留在 Task Root（`core/task-contract.md` §5–6），正式约束留在 ADR、项目规范和已批准文档；记忆只保存摘要与指针，不复制完整副本。

采用 Workflow 时，Main 默认管理目标项目固定目录中的受管文件：创建、筛选、概括、去重、合并、更新、普通到期与容量淘汰、备份与暂存清理在默认范围内，默认维护不逐次请求批准；范围、例外与保留边界见 `core/permissions.md` §1「记忆授权」。规则安装、设计批准或记忆文件自述都不能扩大这个范围。项目或任务明确禁止记忆时，候选留在已获准的 Task Root；要求完全只读、禁止在项目内写文件或 Task Root 不在 Allowed Paths 内时，只在任务上下文记录评估与候选，不创建目录或文件。

长期禁存规则不存放在记忆里。默认依据是 §5 的禁止清单与项目已有约束，不需要为此另建授权 / 隐私文件；确有声明的附加永久禁令时，才需要常设授权指定的可持续读取来源（`core/permissions.md` §1「长期禁存规则」）。核对不到该来源时，相关自动写入暂停并交 Main（§4 步骤 3、§9 防复活）。

## 1. 不变量

1. 无来源、超出授权、含禁止保存内容的候选不进入记忆。
2. 同一适用条件下一个语义事项只有一个规范条目和一个当前有效结论。
3. 未批准的建议不升级为已确认决策；旧任务的授权不继承到新任务。
4. 每次提交满足条目、文件和操作空间硬上限，辅助状态同样受约束。
5. 删除后的内容不再被读取、索引、缓存或未经授权的补录带回。

## 2. 三个逻辑接口

| 接口 | 触发 | 输入 | 输出 | 不负责 |
|---|---|---|---|---|
| 相关读取 | 新任务确认权限与范围后；维护提交后 | 目标与范围、项目根、当前代次 | 有限相关条目及其条件、状态、来源与代次；冲突或过期提示 | 全文件注入上下文、把加载计为有用 |
| 结束评估 | 任务到达明确终态或结果修订 | Task ID、结果版本、目标、终态、验收证据、Main 确认的决策、授权范围 | SKIP / NO_CHANGE / PROPOSE / READY，原因与最多 3 个候选 | 改写业务验收、分析整段对话 |
| 维护提交 | Main 核对候选，默认范围内直接提交 | 变更集、读取时的代次、预期预算、批准依据 | 新代次与写入回执，或不改变当前文件的失败结果 | 多 Agent 各自追加、保存无限历史 |

全部执行者是 Main 与子 Agent 的现有角色，不新增独立 Agent、服务、索引或依赖。Main 是唯一逻辑写入负责人；子任务只向 Main 提供候选，不直接写长期记忆。

## 3. 相关读取

1. 确认项目根、当前授权和任务范围。

   - 完成条件：已记录项目根绝对路径与授权来源。
2. 按任务目标、对象和适用条件选择条目，并过滤已删除、已过期、未验证与冲突条目。

   - 完成条件：候选条目满足目标、对象与适用条件三项匹配。
3. 输出所选条目并携带代次、状态、`scope`、来源与冲突提示，总计不超过 8 条、2,000 个 Unicode 字符；无法保全必要条件时少返回，并说明省略原因。

   - 完成条件：输出在上限内，且可以脱离文件独立理解。
4. 只把本次必需的条目传入子 Agent 的 Contract，不传整份文件。

   - 完成条件：Contract 引用的条目可以由代次和 ID 复核，且没有全量注入。

读取不刷新 `last_verified_at`、`review_at` 或 `expires_at`；遇到语义冲突按 §9 交 Main 决策并标记 CONFLICTED。

## 4. 结束评估

暂停、等待用户、Session 恢复和续接都不是结束：沿用原 Task ID、Task Root 与状态，不新增记忆事件。子任务不独立写记忆，由 Main 在主任务结束时汇总。

1. 确认终态与结果版本。

   - 完成条件：终态为 DONE / PARTIAL / BLOCKED / FAILED / 明确取消之一，且 `outcome_revision` 已由 Main 在任务结束记录中确定；重跑总结不能替代该版本。
2. 记录幂等键 `(project_id, task_id, outcome_revision)` 并查重。

   - 完成条件：已处理事件返回原回执或 NO_CHANGE，条目数与期限不变。
3. 过第一道价值门：信息与当前项目相关且适用对象或条件可说清，已确认或已标注的未解问题，会影响未来的决策、执行、验证或恢复，且不在禁止保存范围内；并至少命中以下一项保留理由。

   - 新的已确认关键决策或约束。
   - 经验证的可复用入口、方法、限制或排障结论。
   - 后续任务必须知道的结果变化、兼容性或迁移影响。
   - 有对象、负责人或重查条件的具体遗留问题。
   - 对现有记忆的纠正、失效说明或重要条件补充。

   - 完成条件：命中全部必要条件，已核对 §5 禁止清单与项目已有禁存约束（附加禁令的来源见 `core/permissions.md` §1「长期禁存规则」），且「投入大 / 对话长 / 代码多 / 用户说完成」不作为理由。声明了附加禁令而来源缺失、不可读取或无法完整核验时本条不通过，候选留 Task Root 并交 Main。
4. 过第二道准入门：候选相对当前记忆有语义增量或可信的重新验证，且授权、来源与预算全部满足。

   - 完成条件：得到下列结果之一；SKIP 与 NO_CHANGE 只写一行原因，不生成叙述性总结。

     | 结果 | 任务总结 | 项目记忆 |
     |---|---|---|
     | SKIP：无价值、仅过程叙述或禁止保留 | 不生成，只记原因 | 不写 |
     | NO_CHANGE：已有结论完全覆盖且无新验证 | 不生成 | 不新增、不刷新期限 |
     | 重复结论但有新验证 | 最小增量说明 | 只更新证据与 `last_verified_at`，不增条目 |
     | 新价值但未授权或存在实质冲突 | 候选留在 Task Root | PROPOSE，不进入有效记忆 |
     | 新价值且准入条件满足 | 精简总结与变更集 | READY |
     | 有价值但预算内无法安全容纳 | 保留候选与拒绝原因 | 不超限，交 Main 取舍 |

5. 有候选时生成任务总结：最多 600 个 Unicode 字符，含任务目标、关键决策（结论、理由、条件、批准来源）、结果（真实终态与验证程度）、遗留问题、可复用上下文；空缺项写 None。

   - 完成条件：五项齐全、字数合规，且每项结论都有证据入口。
6. 写评估结果、候选与回执，按 §6–§10 提交或留在 Task Root。

   - 完成条件：结束评估结果必为 SKIP / NO_CHANGE / PROPOSE / READY 之一；有实际提交时回执取 UPDATED / FAILED / DEFERRED 之一，没有提交时回执写 N/A。两者都写入当前任务 overview 的结束记录，业务验收状态不受影响。

评估与回执是两组独立枚举，只在下表对应：

| 结束评估 | 提交动作 | 回执 | 授权字段 |
|---|---|---|---|
| SKIP / NO_CHANGE | 无提交 | N/A | N/A |
| PROPOSE（未授权或冲突待裁决） | 无提交，候选留 Task Root | N/A；已尝试提交但被阻断时 DEFERRED | 记明缺失或待确认的授权、冲突编号 |
| READY | 有提交 | UPDATED / FAILED | 记明授权来源与代次 |

## 5. 保留与排除

禁止保存的判定同时依据本节默认清单与项目已有约束；声明了附加永久禁令时并入其持续来源，全部取并集，任一命中即排除（来源与核对要求见 `core/permissions.md` §1「长期禁存规则」）。

| 内容 | 保留 | 不保留 |
|---|---|---|
| 任务目标 | 与条目有关的对象、问题和预期变化 | 每个历史任务的完整需求 |
| 关键决策 | 当前结论、理由、条件、批准状态与权威来源 | 讨论轮次和落选方案的长篇描述 |
| 结果 | 已验证的变化、失败限制、兼容与运行影响 | 「完成了」类状态、完整测试日志 |
| 遗留问题 | 仍有效的影响、依赖、负责人与重查条件 | 无下一步用途的担忧、已关闭清单 |
| 可复用上下文 | 稳定术语、模块入口、环境前提、方法与排查线索 | 通用常识、一次性命令、无条件的旧路径 |

禁止保存：凭据、Token、Cookie、连接串、私人对话、真实个人数据、生产业务记录副本、完整堆栈或截图、过时猜测、未授权的跨项目内容。引用证据不是保存敏感信息的旁路。

来源失效时降低可信状态，不以坏链接作为已核验事实。

## 6. 文件、字段与存储

### 6.1 布局

- 路径固定为 `<Project Root>/.agents/workflow/memory/project-memory.md`。`Project Root` 是当前任务的目标项目根，由 Main 在 Intake 解析并记录；它不是用户主目录、Session 目录、Task Root，也不默认是 `AGENT_WORKBENCH_ROOT`。
- 只允许同目录三个受管文件及其用途：`project-memory.md`（当前完整版本，唯一读取来源，`pending` 提交后整体替换它）、`project-memory.previous`（最多一个更新前版本）、`project-memory.pending`（最多一个待提交版本）。后两者不用于普通检索，也不对读者可见。
- 不新建逐任务记忆文件、archive、全量日志、向量索引或候选目录；候选留在 Task Root。
- 记忆目录、备份、暂存和候选都只保存在本地：不进入 commit / push，不外发、不自动同步。初始化时由使用者在该仓库实际 Git 元数据目录的 `info/exclude` 加入 `/.agents/workflow/memory/`；已有等效或父目录规则时复用，不改需提交的 `.gitignore`，不移除已有跟踪，不强推暂存。首次写入前须确认目录已被忽略且其中没有已跟踪文件；条件不满足时保留任务内候选并报告配置问题。
- 新克隆、其他机器和独立工作区按「没有本地记忆」处理，不视为项目事实失效。

### 6.2 文件级字段

| 字段 | 含义 |
|---|---|
| `schema_version` / `policy_version` | 结构与策略版本；不支持的结构拒绝写入，不猜测迁移 |
| `project_id` | 与项目根绑定的身份，防止其他项目混入 |
| `generation` / `updated_at` | 当前代次与提交时间；读取和更新使用同一代次 |
| `limits` | 文件、条目、维护空间与读取上限 |
| `import_floor` | 最早允许导入的历史结果版本时间，防删除后回扫重建 |
| `recent_receipts` | 有限近期回执：Task ID、结果版本、动作、代次、时间 |
| `deletion_markers` | 有限删除/合并标记：条目身份、目标身份、原因码、时间；不含被删正文 |
| `metrics` | 汇总计数与最多 12 个周期桶；不保存逐任务使用日志 |
| `entries` | 规范记忆条目 |

### 6.3 条目字段

| 字段 | 必需性与语义 |
|---|---|
| `id` | 必需，稳定身份；合并和文本改写不改 ID |
| `topic_key` | 必需，项目＋对象＋知识类型＋适用条件的规范主题键 |
| `kind` | 必需，DECISION / CONTEXT / OUTCOME / OPEN_ISSUE |
| `title` / `scope` | 必需，主题与模块、版本、环境、有效条件 |
| `statement` | 必需，一个可核对的当前结论；冲突时并列写出互斥说法 |
| `task_goal` / `outcome` | 必需，来源任务的目标、终态与验证程度；不存在时写 N/A |
| `rationale` / `reusable_context` | 有意义时填写理由与复用线索，否则 None |
| `unresolved` / `owner` / `next_check` | 问题类必需，含影响、责任归属与重查条件；未知负责人写 UNKNOWN |
| `status` | 必需，ACTIVE / NEEDS_REVALIDATION / CONFLICTED；已删正文不以条目继续保存 |
| `evidence_status` / `approval` | 必需，VERIFIED / USER_CONFIRMED / UNVERIFIED；决策保留 Origin 与批准状态 |
| `sources` | 必需，最多 3 个关键来源，含任务或权威文档指针、版本或采集时间 |
| `created_at` / `updated_at` / `last_verified_at` | 必需，创建、内容修订、事实验证时间；未核验时 `last_verified_at` 为 None |
| `review_at` / `expires_at` / `invalidation_conditions` | 必需，复核时间、停止使用时间、事件失效条件 |
| `retention_class` / `protected_reason` | 必需，普通或保护；保护须有批准依据，仍计预算并接受有效性检查 |
| `utility` | 最近证实有用的时间与有限累计次数；仅实际节省调查或纠正决策时更新 |

不使用模型置信分数代替证据。`sources` 超限时保留权威来源、首次必要出处和最新验证，其余历史留在 Task Root。

### 6.4 硬预算

| 项目 | 上限 |
|---|---:|
| 当前文件 | 64 KiB（实际 UTF-8 字节，含标题、字段、来源、标记与统计） |
| 控制与辅助元数据 | 32 KiB，属于当前文件的子预算 |
| 当前条目 | 32 条（ACTIVE、NEEDS_REVALIDATION、CONFLICTED 全计入） |
| 单条 | 序列化 4 KiB，正文 1,000 个 Unicode 字符 |
| 每任务新增候选 | 3 条；修订与分批提交不能绕过 |
| 单条来源 | 3 个 |
| `recent_receipts` / `deletion_markers` | 各 32 项、各最多 90 天 |
| 周期统计 | 最多 12 个桶，更早只留固定汇总值 |
| `previous` / `pending` | 各 1 个、各 64 KiB，随当前文件上限同步收紧 |
| 受管持久与操作空间 | 192 KiB、最多 3 个文件；临时文件不额外占空间 |
| 单次读入上下文 | 最多 8 条、2,000 个 Unicode 字符 |

条目数与字节上限同时执行；32 条不等于 128 KiB 可用，文件上限先到先限。不把多个独立事项塞入超长条目绕过数量限制。软阈值为文件 80%（51.2 KiB）或 24 条；达到任一值，接纳新候选前整理到不高于 44.8 KiB 且不超过 20 条。

### 6.5 开发者手动编辑

开发者可以直接新增、修改或删除记忆内容；目录、名称与预算不受记忆内文本影响，仍以 §6.1–§6.4 为准。

- 人工编辑与维护串行：编辑前暂停该项目记忆维护，完成后恢复；Main 丢弃旧待提交变更集并重新读取当前文件，不用旧缓存、备份或上一代次覆盖人工改动。不新增锁或协调系统。
- 恢复时一次校验结构、必需字段、项目身份与容量。无效或超限时保留人工文件、报告具体问题并暂停相关自动维护；不静默截断、不自动恢复旧版本。
- 人工内容优先保留，但不自动获得事实、批准或期限效力：与正式规范或可信证据冲突时保留待确认，不升级 `evidence_status` / `approval`，不延长 `review_at` / `expires_at`，保护与预算照常适用。
- 手动删除只表示移除当前记忆，不是永久禁存；普通整理不自动从备份或缓存恢复被删条目。真正的新任务重新验证后仍可按规则保存，永久禁存另按 `core/permissions.md` §1「长期禁存规则」记录。

## 7. 概括、去重、合并与冲突

处理顺序固定：授权与敏感过滤 → 价值判断 → 事实概括 → 规范身份匹配 → 冲突检查 → 状态与期限处理 → 预算整理 → 提交与回读。

- 概括：每条只表达一个主题，保留否定、适用条件和证据强弱，先删过程与可从来源获得的细节；无法在单条预算内准确表达时保留权威指针与关键限制，或交 Main，不做有损自动写入。
- 语义重复：对象、结论和条件相同即视为重复，只有真实新验证才更新验证时间；相同事件重复处理返回原回执，不刷新期限。
- 合并：相同主题且互补合并为一个规范条目，保留条件与最重要来源，旧 ID 只留计入删除标记预算的跳转记录。
- 条件差异不是冲突：版本、环境、条件不同时用 `scope` 区分并存，读取不得把测试结论当生产结论。
- 更新：权威规范或已批准修正优先；同一结论再次验证时原位更新证据与期限；替代结论原位替换，历史留在 Task Root 与正式决策文件。
- 冲突：同等级可信来源互相矛盾，或用户确认与现行规范冲突时标记 CONFLICTED，保存两项简短主张与来源，停止作为确定事实输出，交 Main 澄清；不以时间戳或相似度决定胜出。裁决前保持 CONFLICTED；30 天未裁决按 §9 处理。
- 未批准的建议不覆盖已确认决策，候选留在 Task Root。
- OPEN_ISSUE 解决后删除该条目；解决方法本身可复用时转为 CONTEXT / OUTCOME。
- 来源丢失、环境变化或依赖移除时标记 NEEDS_REVALIDATION，核验前不作为执行依据。

## 8. 容量与整理

整理顺序：清到期的标记与操作文件 → 合并重复条目与重复来源 → 压缩非必要叙述 → 把已有正式归属的知识收缩为「结论＋权威指针」 → 按策略淘汰普通条目 → 保留保护项与高影响未解问题。

普通条目淘汰顺序：已过期或已失效 → 已关闭的一次性结果 → 低价值且未复用的上下文；同级按更久未验证、更久未证实有用、稳定 ID 排序。「未被读取」不等于无价值，安全约束不按访问热度淘汰。

目标不可达时保持硬上限、拒绝新增并报告原因；不静默删除关键约束，不以扩容代替整理。扩容需要重要信息遗漏的证据并经用户批准。

不得用逐任务文件、archive 子目录、完整变更日志、无限来源链或无限 tombstone 规避上限。Task Root 属于任务档案，不计入记忆预算，但需单独统计；不得把被淘汰的记忆复制进 Task Root 伪装删除。

## 9. 期限、复核与删除

期限从最后可信核验计算，不从读取、重试或改写计算；无可信核验时间时以 `created_at` 保守起算并保持 NEEDS_REVALIDATION。

| 类别 | 复核 | 硬到期 |
|---|---|---|
| 稳定且已批准的决策 | 180 天，相关契约变化时立即检查 | 普通摘要 365 天未核验则停止使用并移除；有效保护项交 Main |
| 可复用上下文 | 90 天 | 180 天未核验，或对象与环境已不存在 |
| 有后续影响的任务结果 | 30 天 | 90 天；长期有效时提炼为 CONTEXT |
| 未解问题 | 30 天或 `next_check` 提前触发 | 默认 90 天复核是否仍开放；关闭即移除，失联且无法核验则停止作为确定待办 |
| 冲突信息 | 14 天内提交 Main | 30 天未裁决：普通冲突从活动记忆移除正文并记录删除标记与代次，证据只在原 Task Root；重要有效约束保留 CONFLICTED 并交 Main |
| 删除标记 / 回执 | 无内容复核 | 90 天或容量先到，清除前同步推进 `import_floor` |

复核期到但未到硬期限时标记 NEEDS_REVALIDATION；到期未维护的内容在读取时直接过滤，并在下一次提交清理正文。

维护触发：候选写入前、新任务首次读取的轻量失效检查、软阈值达到、项目版本或环境变化、Main 明确纠正或删除，以及活跃项目每 30 天一次完整整理。没有后台机制时，长期无任务的项目不保证按日历即时物理删除，这一限制如实记录。

删除后一致性：

- 期限删除移除正文与内部引用、别名、统计，记录最小删除标记与结果代次；`generation` 随每次提交变化，读取结果携带代次，旧代次不得继续使用。
- `previous` 最长保留 7 天或到下一次正常提交；`pending` 成功或失败处理即清理，遗留最长 24 小时。此时状态是「已从活动记忆删除，备份待清理」，不宣称彻底擦除。
- 恢复旧版本前重新应用当前删除策略、`import_floor` 与删除标记；控制状态丢失时暂停写入，由 Main 明确重建。
- 用户明确删除或发现误写敏感信息时，立即删除全部受管路径中的被删正文与提交中间态文件，不受备份期限制，只保留不含敏感内容的身份与原因码；敏感删除优先于 `pending` 的宽限期。已运行 Agent 读到的内容、历史 Session、Task Root、Git 与外部备份属于另外的删除范围，由 Main 说明持有方与授权，未确认前不报告「所有副本已删除」。
- 冲突到期：普通冲突 30 天未裁决时，从活动记忆移除正文与内部引用，记录删除标记并把 `import_floor` 同步推进；冲突证据只留在原 Task Root。仍生效的重要约束保留 CONFLICTED，继续计预算并阻止新候选准入，交 Main 明确取舍。确定事实读取不返回冲突主张，Main 定向核对冲突内容与原 Task Root 不受此过滤阻碍。后续裁决按有来源与授权的新结果或修订事件写入，重放旧资料不构成裁决。
- 防复活：默认不全量回扫历史任务，只接受当前任务的新结束或修订事件；稳定事件身份与结果版本防止重试伪装成新事实；清理回执或标记时把 `import_floor` 单调推进到被清理事件版本时间之后，早于边界的历史结果不自动导入，补录须 Main 明确批准。真正的新任务重新验证同一知识时可产生新事件，但须先按 `core/permissions.md` §1「长期禁存规则」核对未解除的禁令，命中则不写回，规则缺失或不可核验时暂停该写入。

## 10. 提交、失败与并发

1. 基于读取时的 `generation` 形成完整变更集，提交前重新核对代次与预算。

   - 完成条件：变更集覆盖本次全部动作，且预计容量在硬上限内。
2. 在 `pending` 中校验结构、来源、大小与内部引用后整体发布。

   - 完成条件：读者只能看到旧完整版本或新完整版本，没有半写状态。
3. 以发布结果对齐回执：提交成功后按已发布且回读验证的 `generation` 与幂等键写入记忆回执，Task Root 只负责长期追溯，并与该代次对齐。

   - 完成条件：回执的代次、动作与已发布文件一致；Task Root 回执缺失或不一致时先回读当前文件与近期回执，不自动覆盖已发布内容。

- 代次已变化：放弃陈旧变更集重新协调，不覆盖他人刚完成的纠正或删除。
- 写入失败、容量不足或权限缺失：旧权威文件保持有效，回执标 FAILED / DEFERRED，候选留在原任务；不先删旧数据再尝试写新文件。
- 提交成功但回执未写入：按近期幂等信息回读，以已发布代次重写回执，不重做提交也不覆盖已发布内容。
- 回读校验项目身份、代次、实际容量、变更动作与无悬空引用，成功后才报 UPDATED。
- 备份损坏不能替代当前文件核验；敏感删除后的备份不得恢复。

## 11. 评估与已知限制

只有同时说明「体积受控」和「重要知识未被无差别删除」才算有效。周期评估使用受限统计，不建立新的记忆日志。

| 维度 | 口径 | 初始目标 |
|---|---|---|
| 硬约束 | 每次提交的字节、元数据、条目、辅助文件与峰值 | 超限 0；峰值 ≤192 KiB |
| 稳态增长 | 重复知识序列中的条目与字节变化 | 100 次重复不增条目、不刷新期限，总量不随任务数线性增长 |
| 增量可解释性 | 净增长是否对应新主题、来源是否受限 | 每次增长可归因 |
| 去重质量 | 抽查条目中的语义重复对 | ≤5% |
| 保留质量 | 人工标注的重要事实仍可检索的比例 | ≥95%，关键约束漏保 0 |
| 读取质量 | 返回条目与当前任务相关的比例 | ≥80%，条件与来源完整 |
| 过期与冲突 | 把到期或未决冲突当确定事实的次数 | 0 |
| 删除一致性 | 删除后自动重放、旧代次或备份恢复的复活次数 | 0，敏感删除正文残留 0 |
| 维护成本 | 候选处理、核验与整理所需时间 | 不随完整历史任务数线性增加 |
| 实际复用 | 有证据的节省调查或避免错误次数 | 与「仅加载」分开统计 |

评估流程：人工标注样本（无价值、重复、真实增量、冲突、过期、敏感删除、失败任务）→ 与「每任务都记」基线比较 → 不少于 1,000 个结束事件的离线模拟（含长重复序列、连续新主题、满容量保护项、中文、来源数组、标记过期与恢复）→ 至少 30 个真实任务试运行 → 每 30 天复核增长来源。先调筛选与压缩，扩容须用户批准。

本文件定义规则，不证明实现效果：原子提交的并发行为、实际检索准确率与运行成本需在启用后按上表实测，未实测项标为 NOT VERIFIED。

## 12. 边界场景

| 场景 | 应有行为 |
|---|---|
| 无价值的文字调整或简单查询 | SKIP，不新增条目，不为每次 SKIP 追加日志 |
| 有价值的小任务 | 按内容而非级别保留，L0/L1 不一刀切排除 |
| 同一事件重复提交 | 返回原回执或 NO_CHANGE，条目数与 `last_verified_at` 不变 |
| 多任务语义重复 | 合并同一主题，只更新核验增量，来源始终 ≤3 |
| 同一主题不同环境 | 用 `scope` 并存，读取区分测试与生产结论 |
| 同等级证据冲突 | CONFLICTED 交 Main，确定事实检索不返回冲突主张 |
| 冲突 30 天未裁决 | 普通冲突移出活动正文并同步标记与 `import_floor`，证据留原 Task Root；重要有效约束保留 CONFLICTED 并交 Main，仍计预算 |
| 未批准建议覆盖已批准决定 | 候选留 Task Root，已批准状态不变 |
| 任务取消、失败或部分完成 | 只保留已证实事实，`outcome` 如实，不把未完成目标写成达成 |
| Session 恢复或父子任务 | 续接原档案，主任务统一评估，不触发额外事件 |
| 问题关闭或对象删除 | 删除问题条目并失效相关上下文，读取无过期待办 |
| 保护项占满预算 | 拒绝新增交 Main，永不超限，不静默淘汰约束 |
| 标记过期后重放旧任务 | `import_floor` 与原任务回执阻止自动写回，补录须批准 |
| 长期禁存规则存在 | 结束评估与新事件写入先核对 §5 禁止清单与项目已有约束，声明了附加禁令时并入其持续来源，命中则不写回；附加来源缺失或不可读时暂停写入交 Main |
| 来源丢失 | 降为 NEEDS_REVALIDATION，不当作最新验证 |
| 正常删除后仍有 `previous` | 不可检索，报告备份待清理，不宣称彻底擦除 |
| 明确敏感删除 | 受管路径与提交中间态均无被删正文，历史 Session 范围单独披露 |
| 写入中断、回执超时或陈旧代次 | 回读确认，旧完整版本可用，不半写、不重复增条目 |
| 维护长期未运行 | 读取仍过滤到期内容，不依赖物理删除完成停止使用 |
| 中文或大量元数据 | 同时按 UTF-8 字节与字段上限检查，字符合规但字节超限即拒绝 |
| 项目根与工作流安装根不同 | 写入目标项目的固定路径，不误写安装根或用户全局目录 |
| 记忆目录未被忽略或已有跟踪 | 停止长期写入并报告，不自动暂存、提交或移除跟踪 |
| 新克隆、其他机器或独立工作区 | 按缺少本地记忆处理，不按 Git 同步，不视为事实失效 |
| 普通项目有准入价值的结束（未另写常设授权或隐私文件） | 默认维护直接执行，不逐次请求批准；仍过价值门、准入门与预算 |
| 项目或任务明确禁止记忆（但仍可写 Task Root） | 候选、评估与回执留在 Task Root，不写受管文件 |
| 完全只读或 Task Root 不在 Allowed Paths 内 | 只在任务上下文记录，不创建目录或文件；内部产物不构成隐含豁免 |
| 人工编辑后结构无效或超限（缺必需字段或超出容量） | 保留人工文件并报告，暂停相关自动维护；不静默截断、不自动恢复旧版本 |
| 人工删除与永久禁存（声明永久不保留某类内容） | 手删只移除当前，新验证可再记；永久禁存按持续来源核对，来源缺失则暂停对应写入 |
