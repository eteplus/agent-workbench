# 项目记忆

项目记忆用于跨任务保留**少量、高价值、代码本身无法自明**的项目特定约束与踩坑经验。任务过程留在 Task Root，架构规范留在 ADR / `AGENTS.md` / 项目文档；记忆文件不记录过程流水账。

## 1. 定位与边界

- **固定路径**：`<Project Root>/.agents/workflow/memory/project-memory.md`（按目标项目根解析，绝不写到 `AGENT_WORKBENCH_ROOT` 或用户主目录）。
- **仅限本地忽略保存**：记忆文件默认不提交、不外发。首次创建前，Main 确认该路径已被目标仓库忽略（未忽略时写入仓库 Git 元数据目录的 `info/exclude`：`.agents/workflow/memory/`）且未被 Git 跟踪；若目录已被跟踪则停止写入并报告配置问题。
- **权限与只读回退**：采用 Workflow 时由 Main 默认维护（单写者），不逐次请示；子 Agent 不直接写该文件。项目或任务明确禁止记忆但允许写 Task Root 时，仅在 `overview.md` 记录候选；任务要求完全只读、禁止在项目内写文件或 Task Root 不在 Allowed Paths 内时，只在任务上下文记录，不创建任何目录或文件。

## 2. 预算与格式

使用纯文本 Markdown 结构，硬预算上限：

- **文件总大小**：不超过 `16 KiB`（UTF-8 字节）。
- **条目总数**：不超过 `25` 条；单次任务最多新增 `2` 条。
- **Intake 按需读取**：新任务在 Intake 仅提取与当前模块相关的条目（最多 `5` 条、不超过 `1,000` 字符）写入 Contract `Context & Plan`，不整份注入无关条目。

推荐单条紧凑格式：

```markdown
- **[M-01]** (`scope`: `apps/web` | 更新: `YYYY-MM-DD` | 来源: `<task-id> / ADR-001`)
  结论与可复用约束（1–3 句，含适用条件与验证方式）。
```

## 3. 准入与默认跳过

任务到达终态（Acceptance 完成）时，Main 做一次轻量判断，结果取 `SKIP`、`UPDATED` 或 `PROPOSE`（未获写权限时仅留候选），记录在 `overview.md` 一行即可，不改变业务 Verdict：

- **默认 `SKIP`（常规任务默认路径）**：凡是结论已体现在源码类型、测试用例、仓库文档、ADR 或外部 Issue 中的常规功能/修复任务，一律 `SKIP`，不生成任务总结，也不更新记忆文件。
- **准入条件（仅记真正省时间的隐性知识）**：
  1. 跨任务反复踩坑的环境限制、构建/测试特殊前置命令（如特定隔离库启动方式）。
  2. 用户明确跨任务生效、且尚未写入 `AGENTS.md` 的项目偏好或禁令。
  3. 影响后续开发的未解高风险边界（注明重查条件，解决后立即删除）。
- **严禁保存**：API Key、Token、Cookie、连接串、个人隐私数据、生产业务数据、一次性任务进度、完整报错堆栈及未经验证的猜测。

## 4. 更新与人工编辑

- **去重与淘汰**：同一主题原位更新，不追加重复条目；发现条目与最新源码/规范不符或问题已关闭时直接删除。接近 `25` 条或 `16 KiB` 时，优先清理已落入正式文档的条目和最久未复用的普通上下文。
- **尊重人工编辑**：开发者可直接手动增删改 `project-memory.md`。Main 写入前先读取当前最新文件合并变更，写入后回读校验完整性与容量上限，保留开发者手动编写的内容，不静默截断或用旧内容覆盖；若人工改动导致超出容量或与现行规范冲突，暂停自动覆写并向用户说明。
